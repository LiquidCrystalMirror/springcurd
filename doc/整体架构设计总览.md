# 整体架构设计总览

> 面试要点：为什么要 Redis 主存储 + MySQL 异步持久化？技术选型的依据是什么？架构的演进方向？

---

## 一、项目定位

一个面向电商大促场景的**高并发库存扣减系统**，核心挑战：
1. 高并发下防止超卖
2. 库存变更的可靠持久化
3. 取消订单的数据一致性

## 三、核心数据流

### 3.1 下单流程

```
POST /orders/add
  │
  ├─ ① 合并相同商品数量
  ├─ ② Lua 脚本原子扣减 Redis 库存
  │     ├─ 幂等检查 (biz:idempotent:deduct:{bizNo})
  │     ├─ 库存充足性检查
  │     ├─ 批量扣减 (INCRBY 负数)
  │     ├─ 保存快照 (biz:snapshot:deduct:{bizNo})
  │     └─ 写幂等标记
  ├─ ③ 返回成功 (200)
  ├─ ④ RabbitMQ 异步发送扣减消息
  │     ├─ 本地消息表写入 (status=0)
  │     └─ 发送 → 更新 status=1
  └─ ⑤ MQ 消费者：订单明细持久化到 MySQL
        ├─ INSERT order_detail
        └─ INSERT biz_idempotent (status=1)
```

### 3.2 取消订单流程

```
POST /orders/cancel
  │
  ├─ ① 查询订单明细 (order_detail)
  ├─ ② 校验订单状态 (status=1 才可取消)
  ├─ ③ Lua 脚本恢复 Redis 库存 (cancel.lua)
  │     └─ 幂等检查 (cancel:idempotent:{bizNo})
  ├─ ④ 更新 order_detail status → 0 (带指数退避重试)
  ├─ ⑤ 更新 product_stock 表 (乐观锁 + 重试)
  │     └─ 从 Redis 读取最新库存值
  ├─ ⑥ RabbitMQ 异步发送回滚消息
  └─ 返回结果 (允许部分商品失败)
```

## 四、技术选型依据

| 选择 | 备选方案 | 选择理由 |
|------|----------|----------|
| Redis 主存储 | MySQL 主存储 | 内存操作，微秒级响应；Lua 脚本原子操作保证并发安全 |
| Lua 脚本 | 分布式锁 (Redisson Lock) | 减少网络往返，原子性更强，无需管理锁超时 |
| RabbitMQ | RocketMQ / Kafka | 生态成熟，Spring AMQP 集成简单，适合中小规模 |
| 本地消息表 | RocketMQ 事务消息 | RabbitMQ 不支持事务消息，本地消息表是最小的补偿方案 |
| Resilience4j | Sentinel / Hystrix | 轻量，Spring Boot 3 原生支持，函数式设计 |
| BCrypt | MD5 / SHA256 | 自适应 cost 因子，内置盐值，抗暴力破解 |
| 乐观锁 | 悲观锁 (SELECT FOR UPDATE) | 冲突概率低，无锁等待，并发性能更好 |
| 手写 TraceId | SkyWalking / Zipkin | 单体应用无需重型 APM，轻量实现成本极低 |
| MyBatis-Plus | JPA / 原生 MyBatis | 国内生态主流，Lambda 查询简洁，分页插件成熟 |

## 五、异常处理体系

```
业务异常体系（6 种子类）：
  BadRequestException       → 400 参数错误
  UnauthorizedException     → 401 未登录
  ForbiddenException        → 403 无权限
  NotFoundException         → 404 资源不存在
  ConflictException         → 409 幂等冲突
  ServiceUnavailableException → 503 熔断限流

兜底异常：
  RuntimeException          → 500 未知错误
  DataAccessException       → 500 数据库异常
```

通过 `GlobalExceptionHandler`（`@RestControllerAdvice`）统一捕获，返回 `ApiResult` 格式。

## 六、响应体设计

```json
{
  "code": 200,
  "message": "success",
  "data": { ... },
  "errorCode": null,
  "traceId": "a1b2c3d4e5f6g7h8",
  "timestamp": "2026-07-14 10:00:00.123"
}
```

| 字段 | 说明 |
|------|------|
| `code` | HTTP 状态码 |
| `message` | 人类可读信息 |
| `data` | 业务数据（`@JsonInclude(NON_NULL)` 空时不序列化） |
| `errorCode` | 业务错误码（如 `STOCK_INSUFFICIENT`） |
| `traceId` | 链路追踪 ID（从 MDC 获取） |
| `timestamp` | 响应时间戳 |

## 七、安全体系

```
┌─────────────────────────────────────┐
│           安全分层                    │
├─────────────────────────────────────┤
│ 传输层                               │
│   JWT 双 Token（Access + Refresh）   │
│   Token Rotation（防重放攻击）        │
├─────────────────────────────────────┤
│ 认证层                               │
│   JwtAuthInterceptor                 │
│   白名单路径（登录/注册/公开API）      │
├─────────────────────────────────────┤
│ 鉴权层                               │
│   RoleInterceptor（管理员/普通用户）   │
│   StatusInterceptor（用户启用/禁用）   │
├─────────────────────────────────────┤
│ 密码安全                             │
│   BCrypt 加密（cost=10）             │
│   MD5 旧密码向后兼容                  │
├─────────────────────────────────────┤
│ 防攻击                               │
│   登录限流 5 req/s（防暴力破解）      │
│   下单限流 20 req/s（防恶意刷单）     │
└─────────────────────────────────────┘
```

## 八、已知局限与改进方向

| 当前局限 | 改进方向 |
|----------|----------|
| 单体应用 | 微服务拆分（订单服务/库存服务/用户服务） |
| Docker Compose 部署 | K8s 集群部署 + 弹性伸缩 |
| 无分布式事务 | 引入 Seata TCC/Saga 模式 |
| 无消息重发补偿 | 加 Quartz 定时任务扫描失败消息 |
| 无缓存预热 | 系统启动时从 MySQL 加载库存到 Redis |
| TraceId 不支持跨服务 | 升级为 SkyWalking Agent |
| 无 CI/CD | 接入 Jenkins/GitHub Actions |
